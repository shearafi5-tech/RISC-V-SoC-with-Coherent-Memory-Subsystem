2.1 Data Flow Summary

 1. Core fetches instructions from private I-SRAM (never through coherence).
 2. Core data accesses go through its private D-cache manager.
 3. D-cache manager talks to the shared SRAM via AXI4-Lite.
 4. On a write, the coherence controller is notified and invalidates the remote cache line.
 5. On a read miss (or post-invalidation), the cache refetches from shared SRAM.

3.5 AXI4-Lite Arbiter ( axi_lite_arbiter )

Property       Value
Masters        2 (one per core's D-cache manager)
Slaves         1 (via address decoder)
Arbitration    Round-robin (or fixed priority)
Deadlock-free  Yes -- each transaction has bounded completion

Arbiter Logic: At any idle point, grant the master that has been waiting longest. Once a master is granted, it
holds the bus until its transaction completes (AXI4-Lite: one AW+W+B, one AR+R).

4.2 Transaction Scenarios

Scenario A: Core 0 writes, Core 1 reads (the core demo)

1. Core 0: SW r1, 0(shared_addr)  D-cache 0 write-through             1 line
2. D-cache 0  AXI write to shared SRAM                                gets new
3. Coherence controller: Core 0 line  M, notify invalidation of Core
4. Core 1 D-cache: invalidate line  I
5. Core 1: LW r2, 0(shared_addr)  miss (state=I)  fetch from SRAM 
value

Scenario B: Simultaneous writes to same address
?   1. Both cores issue SW to same addr in same cycle
   2. Arbiter picks winner (e.g., Core 0 by round-robin priority)
   3. Core 0 writes  Core 1 line invalidated
   4. Core 1 writes  Core 0 line invalidated
   5. Final SRAM value = last writer (Core 1, second in arbiter order)
   6. Both caches end in I state for that line

Scenario C: No cached copy in other core

   1. Core 0 writes to addr A
   2. Coherence controller checks: Core 1 has no valid copy of A (state=I)
   3. No invalidation sent -- Core 0 line  M

12. Verification Architecture

12.1 Directed TB

Self-checking testbench in SystemVerilog:

  · Instantiates riscv_soc_top .
  · Preloads I-SRAMs with test programs ( $readmemh ).

  · Monitors UART output, MMIO counters, and shared SRAM.
  · Self-checks: asserts expected values after each coherence scenario.
  · Test cases: reset, normal read/write, cache hit, cache miss, cross-core invalidation, simultaneous write,

    error/unmapped access.

12.2 UVM Environment

Core 0 Sequences                       uvm_env                                              Core 1 Sequences
(randomized reads/writes)                                                                   (randomized reads/writes)

                  Agent 0              Agent 1                Coherence Monitor
                  (Core 0 AXI master)  (Core 1 AXI master)    (snoops invalidate bus)

                                       Scoreboard                                           Coverage Collector
                                       (predicts shared SRAM                                (states, events, hit/miss)
                                       state)

UVM Components:

  · Agents (×2): AXI4-Lite master agent per core -- driver, monitor, sequencer.
  · Sequences: constrained-random read/write sequences to shared SRAM addresses.
  · Scoreboard: predicts expected shared SRAM value based on transaction order; compares with actual.
  · Coherence Monitor: independently observes invalidation events; verifies invalidations fire on every cross-

    core write.
  · Coverage: functional coverage for coherence states (I/S/M per core per line), hit/miss, invalidation count,

    simultaneous-write winner, error responses.
